# How to work here

Written from a long multi-agent session that went badly before it went well. Every rule below is
something that actually cost time or produced a wrong answer, not a preference.

## Verify, never relay

**Check every claim against the tree yourself.** Claims that arrived from agents and were wrong:
"the registry returns duplicates", "`os/user` blocks a static build", "the plugin needs the binary",
"the testing workers failed" (they were still running). Every claim checked held or produced a real
bug; every claim relayed unchecked was wrong.

**Measure in the environment that fails.** A bug that passes locally and fails in CI is not
diagnosable by reading code. A confident, specific, wrong diagnosis cost a day: the real cause was a
lazy `restart` publishing one event, found by instrumenting a CI run, not by reasoning.

**Never test a system against itself.** Driving mcpx's own `server/discover` against mcpx proved both
halves agreed, not that either was right — they shared the same wrong field name. Test against the
schema, the spec, or a reference implementation.

**Check your own state before citing it.** "I'm nearly out of context" was asserted a dozen times at
20% remaining, and was used to justify delegating work that would have been faster inline.

**Every number carries its commit and the command that produced it.** Conformance figures were
reported as 117/54, 116/54, 109/62 and 110/62 in one session; one of them had no source at all.

## Exit codes and pipelines

`cmd | grep x; echo $?` reports **grep**. `cmd | tail -3; echo $?` reports **tail**. This produced a
false "build passed" twice in one session, by two different agents. Redirect to a file and read the
real status.

## Tests

- **Every fix gets a test that fails without the fix.** No exceptions.
- **Confirm the mutation applied.** `grep -c MUTATION` before trusting a result. Several
  "passes either way" conclusions came from a scratch edit that never matched anything.
- **A test that cannot fail is worse than no test**, because it is cited as evidence. One guard
  iterated `name` and then asserted on the constant `"greet"`. Another compared zero tools against
  zero tools and passed. Add a positive control: fail loudly when the premise is empty.
- **Never change a test to accommodate a bug.** When a test broke because `restart` did not restart,
  the test was changed. The bug then survived another fifteen hours.
- **Read the check result before merging.** `DIRTY` means a conflict and CI never ran.

## Fix, do not defer

- **If it is in reach, fix it.** Filing an issue is not progress. The backlog grew 140 → 150 while
  one-line bugs sat in it, because every investigation ended in an issue instead of a commit.
- **Do not defend accidental behaviour as "the design"** when it contradicts the command's name, its
  help text, or the docs. "A lazy pool restarting nothing is the design" defended a bug.
- **Classifying is not fixing.** "55 of 62 failures are fixture mismatches, not defects" was true and
  stopped the work. The fix was to run the suite against its own reference server.
- **Tracking infrastructure is not a fix.** Registers, matrices and comparison documents consumed most
  of a session's budget and fixed nothing. Build them only with a guard that regenerates them.

## Generated documents

Any document that states status must be **regenerated by a guard test that fails on a diff**. A
hand-pinned commit (`requirements.md:7` said `05c78b2`) and a hand-kept PR list both went stale, and
the staleness disclosure itself went stale. The worst case is a conformance matrix reporting `tested:`
and `**gap**` for the same requirement from the same commit — it gets cited as evidence.

"The document says X, the code does Y" is this codebase's signature defect (mcpx #177). When you find
one, write the guard that would have caught it.

## Delegation

**Fan out for breadth; never for depth.** Independent items in parallel works. One causal chain does
not: three agents on a single bug produced a deleted branch, stolen commits, and ninety minutes of
duplicate gating.

**The shape that worked** (seven items, one session, no collisions):
1. The coordinator writes **one shared brief file** and points every worker at it.
2. Each worker owns a **disjoint item**, its **own worktree and branch**, and names any shared file it
   had to touch.
3. Workers **commit and push, and do not open a PR**.
4. The coordinator merges every branch into **one branch** and opens **one PR**.

**What fails:** architects spawning workers that spawn workers; ending a turn with workers still
live; one PR per fix, each taking hours to gate; opening a PR from another agent's branch; launching
a supervisor without first checking what already merged (this cost eleven duplicate issues once and
an hour of re-derived work another time).

**Before launching anything:** `gh pr list`, recent merges, recent branches, recent worktrees.

**One worktree per agent.** Agents have deleted and pushed over each other's. Never work in another
agent's worktree, and never in the session's default checkout.

**Do small things inline.** Delegation costs a full model turn before any work happens.

## Writing to the user

- **Plain words.** Project jargon invented by an earlier agent — "autonomy ceiling", "adapted binary",
  "confinement" — must be defined on first use or avoided.
- **Lead with the correction.** If something you said earlier was wrong, say so first and plainly,
  and say what it cost.
- **State the plain fact before the framing.** "The nix build tests 17 of 32 packages; CI tests all
  of them" beats "the guards are not in the shipping gate".
- **Answer what was asked.** Nothing else.
- Append the moments worth remembering to `~/git/ai_recordings.jsonl` (see `recordings.md`).

## mcpx specifics

- The signature defect is **declared but not delivered** (#177): a flag parsed and dropped, a
  capability advertised and never sent, a setting read but inert. `consumed_test.go` proves a setting
  is *read*, not that reading it changes anything.
- The daemon is keyed by its **config file set**. Three separate bugs came from this; environment
  differences that should produce different daemons do not.
- On macOS `/tmp` is a symlink to `/private/tmp` and the product canonicalises paths, so a test using
  `os.MkdirTemp("/tmp", …)` passes on Linux CI and fails on every Mac. Four test files hit this.
- `nix build`'s `checkPhase` has had a hand-maintained package list that drifted from the packages
  that have tests. CI runs `go test ./...` and does not.
- The official conformance suite ships its own fixture server. Running it against a different server
  measures nothing. **A falling score can mean the code got more correct** — it has, twice.
- Under parallel agents, load averages above 150 push `internal/e2e` past its default timeout. Raise
  `-timeout`; do not read it as a failure.
