# MCP normative requirements, every revision, both sides

WP6 output 1. Merged from five area sweeps (`wp6-raw/A..E.md`, which keep the per-area source lists, conventions and implied-details notes). Sources: prose of every page under `docs/specification/<rev>/`, `schema/<rev>/schema.ts` doc comments, `docs/extensions/tasks/overview.mdx`.

Columns: `id` | `revs` (a range `a..b` when unchanged) | `side` | `level` | `area` | quote | URL | applies to mcpx as server | as client | `changes` (non-empty = the obligation differs in another revision or is contradicted elsewhere; the full list is `revision-conflicts.md`).

Conventions carried from the sweeps: level `(schema)` / `(implied)` / `(lowercase)` / `(changelog)` qualifiers mark where the keyword came from; side also uses `auth-server` and `intermediary` where the spec addresses them. The two mcpx columns are a reviewer's notes, not a status: the status of each requirement is `conformance-matrix.md`, computed from the tests. A note containing the word `gap` (any case) claims mcpx does not meet the requirement; `TestMatrix` (`internal/conformance`) fails when a cell carrying that claim has a covering test, so a note cannot keep claiming a gap after the fix lands, nor a test pass while a note says it should not. Anchors are heading slugs derived by hand, not checked against the live site. 2024-11-05 and 2025-03-26 have no schema page; schema-only rows for them link GitHub `schema.ts`.
